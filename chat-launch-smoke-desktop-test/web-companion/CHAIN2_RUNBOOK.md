# Chain2 — универсальные разработчики и ревьюеры с передачей контекста

## Схема

DEVELOPER → REVIEWER → следующий DEVELOPER → REVIEWER. **В начале работы агент никого не создаёт.** В конце он через Local Workspace MCP вызывает ровно один идемпотентный запрос на преемника. Это ещё не открытие вкладки: сервер ждёт финальный отчёт, проверенный SHA/ACK и подтверждённый статус DONE, затем выдаёт преемника из заранее согласованного backlog.

Разработчик делает содержательный код и тесты. Ревьюер независимо повторяет тесты, исследует дефекты, оценивает предложения новых фич и передаёт выводы дальше. Предложения фич не меняют утверждённый backlog и не разрешают deploy/merge.

## Наследование информации

Каждый агент в собственной папке сохраняет `handoff.json` (до финального отчёта), с полями:

- `version: 1`, `parent_job_id` — текущий UUID;
- `upstream_handoff` — точный путь к handoff предыдущего агента либо `null` для корневого;
- `summary` — что выполнено;
- `changed_files` — реально существующие файлы в папке своей роли (проверяется файловой системой);
- `tests` — результаты реальных проверок;
- `issues` — ошибки и оставшиеся риски;
- `feature_proposals` — предложения фич **для ревью, не на автоматический запуск**;
- `next_focus` — конкретная следующая работа.

Пакет проверяется по схеме, путям и SHA. После создания handoff агент запускает через Local Workspace MCP:

```text
run_script(
 workspace="projects",
 path="chat-launch-smoke-desktop-test/web-companion/chain_campaign.py",
 cwd="chat-launch-smoke-desktop-test/web-companion",
 args=["request","--parent","<текущий-job-id>"]
)
```

Нужно проверить `job_status: completed / returncode=0`, а в `job_output` — `ok=true`. Только после этого агент создаёт единственный отчёт `agent-reports/completion-<job-id>.md` с `Job ID`, `## Outcome`, `## Evidence`, `## Tests`, `## Handoff`.

**Важно:** `request` не открывает новый чат сразу. Он атомарно фиксирует ровно одну заявку на преемника (`bridge-state/handoff-requests/<job-id>.json`). При повторе с тем же неизменённым handoff возвращает `already_requested=true`; при изменившемся файле — конфликт, без нового агента. После report ACK и финального `/v1/result` браузерный контроллер может получить задачу преемника. Отсутствие handoff или заявки блокирует ACK и закрытие вкладки.

## Backlog / лимиты

`role-campaigns/chain2.json` — параметры 25 связанных с OpenSpec/SDD инженерных тем из `sdd1.json`, **две роли** (50 этапов) и десять стартовых цепочек (seed lanes), продолжающих 10 завершённых исследований `backlog-unblock-20261103`. Каждая роль запрашивает ровно одного преемника в конце после файлов и проверок. По достижении конца согласованного backlog терминальный агент передаёт отчёт и получает `successor=null`: система не придумывает лишнюю работу и не размножает агентов бесконечно.

Глобальные ограничения — максимум 25 активных вкладок/задач; в кампании OpenSpec/SDD максимум 10 ожидающих заданий. Каждая ветка конечна: после 50 заранее описанных ролей новых заданий нет. Поскольку реальные задержки и лимиты ChatGPT различаются, длительность работы не гарантируется. Метрики `chain_metrics.py` отдельно показывают ожидание, send→handoff, send→report и server DONE; никакой «чистой длительности размышления LLM» из этих данных не выводится.

```powershell

python -m unittest discover -p test_*.py -v
```

После архивирования 29 старых записей без повторных отправок, снятия старого `admission-hold`, проверки браузерного профиля, пустой очереди, чистой регрессии и независимого smoke разрешён управляемый запуск:

```powershell
python chain_campaign.py arm --confirm-owner-arm
```

Это create-only arm-маркер с хешем конфигурации, не безусловный запуск 50 браузерных вкладок. Сервер автоматически пополняет очередь только для уже вооружённой кампании. Убирание или изменение arm, появление hold, несовпадение SHA брифа/предшественника или отсутствие подтверждения браузера блокируют выдачу.

**Статус 2026-11-03:** 127/127 тестов Python пройдены, `chain2` вооружена по запросу пользователя с 10 root lanes и 50 максимум этапами. Начальная партия: 4 ACTIVE / 6 QUEUE (проверка после arm). Переходы к преемникам доказаны тестом с 4 hops; реальные handoff/ACK/DONE у Chain2 пока должны быть подтверждены после завершения первых чатов. Старые архивные записи не объявлены DONE, P085 остаётся открытым.

## Проверки

`test_chain_campaign.py` проверяет двухролевую последовательность, восемь корневых задач, отсутствие создания в начале, контекст через handoff, один идемпотентный запрос преемника, защиту от подмены файлов, отказ при обрыве цепи, окончание backlog. В отдельном HTTP-тесте реальный локальный тестовый bridge принимает claim, отклоняет ACK до handoff, принимает report ACK и DONE, после чего выдаёт один REVIEWER с правильным ticket ID. `test_bridge.py` проверяет интеграцию с gate и защиту от досрочной финализации. Все тесты запускаются в изолированной временной файловой системе.

Никакие изменения вне своего ролевого каталога, обход лимитов, Git/deploy/production edit этим контуром не разрешаются. Единственное разрешённое продолжение — одна идемпотентная заявка через Local Workspace `chain_campaign.py request` в конце роли; браузерный контроллер создаёт чат только после родительского ACK/DONE и в рамках лимита кампании.
