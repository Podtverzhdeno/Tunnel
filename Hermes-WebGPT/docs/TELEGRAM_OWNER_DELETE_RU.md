# Hermes — удаление своего сообщения в Telegram

**Статус на 11.11.2026:** функция реализована в локальном исходном коде Gateway и прошла **22 изолированных теста без сетевых обращений**. Совместимость с установленным SDK проверена инспекцией `GatewayRunner._handle_message`, `TelegramAdapter._build_message_event`, `TelegramAdapter.delete_message`. **Живое удаление в Telegram и активация в уже работающем процессе не подтверждены**: после изменения `gateway_bootstrap.py` нужен контролируемый перезапуск, затем отдельный пользовательский тест.

## Как пользоваться

1. Найдите **своё** сообщение в личном чате с Hermes или в групповом топике, где присутствует бот.
2. Нажмите **«Ответить»** на это сообщение (не на сообщение бота).
3. Отправьте **`/delete`** или **`Удали это сообщение`** как ответ.
4. Дождитесь результата. Только сообщение с ID в `reply_to_message` является целью. Ни история, ни соседние сообщения, ни сообщение-команда не удаляются.

Для команды без ответа Hermes должен написать, как правильно ответить на сообщение. Фраза-вопрос вроде «А ты можешь удалить моё сообщение? Вот это» **сама по себе не вызывает удаление** — сначала нужно дать явную команду.

## Технический принцип

Путь: оригинальный апдейт Telegram → существующий Hermes Gateway → `telegram_delete_control.install_telegram_delete_handler` → проверка Telegram-идентичности и `reply_to_message` → резервирование уникального `platform_update_id` в приватной SQLite → **один** вызов `TelegramAdapter.delete_message(chat_id, message_id)`.

Выполняются проверки:

- запрос не является внутренним, пересланным или анонимным `sender_chat`;
- `event.source.user_id`, `raw_message.from_user.id` совпадают с владельцем, а Gateway допускает пользователя через `_is_user_authorized`;
- `raw_message.chat.id` и `message_id` совпадают с нормализованным событием;
- существует **явный ответ** на сообщение того же владельца, того же чата и — если идентификатор известен — топика;
- возраст сообщения подтверждается меткой `date` и меньше 48 часов;
- `platform_update_id` записан до сетевого обращения; повторный апдейт после сбоя или перезапуска не вызывает повторного удаления.

**Не передавайте на удаление произвольные `chat_id` и `message_id`, придуманные моделью.** Отдельный MCP Telegram outbound bridge не владеет потоком входящих апдейтов и не может достоверно удостоверить, кому принадлежит сообщение; поэтому безопасная команда реализована на стороне Gateway.

Бот Telegram может удалять входящие сообщения в личном чате. Для удаления в группах нужны соответствующие полномочия; в супергруппах обычно требуется `can_delete_messages`. Ограничения для удаления, включая 48-часовое окно и исключения для отдельных системных сообщений, определяет [Telegram Bot API](https://core.telegram.org/bots/api#deletemessage). Ошибки API не маскируются обещанием успеха.

## Локальная интеграция

В локальной установленной версии `gateway_bootstrap.py` после подключения `GatewayRunner` и пользовательской Telegram-авторизации добавлено:

```python
telegram_owner_delete = os.environ.get("HERMES_TELEGRAM_DELETE", "1") == "1"
if telegram_owner_delete:
    from telegram_delete_control import install_telegram_delete_handler
    install_telegram_delete_handler(
        GatewayRunner, profile / "telegram-delete-requests.sqlite3"
    )
```

В опубликованной версии `gateway_bootstrap.py` нет всех локальных overlay-патчей. **Не заменяйте рабочий bootstrap старой публичной копией**: интегрируйте эту часть в текущий файл с CAS/SHA, затем выполните безопасный перезапуск только при отсутствии активных задач. Отключение после следующего запуска: `HERMES_TELEGRAM_DELETE=0`.

SQLite хранит числовые идентификаторы апдейта, чата и цели и состояние попытки, но не содержимое сообщений и не токен бота. Локальный `profile/` не должен попадать в GitHub.

## Проверка

Из корня рабочей копии `Hermes-WebGPT` с установленным Hermes SDK и локальным модулем авторизации:

```powershell
python -m unittest -v test_telegram_delete_control
```

На Windows результат: **22/22 PASS**, без реальных вызовов Telegram. Проверены успешная команда и естественная императивная фраза, DM и группа, отказы при чужом авторе, другом чате/топике, пересылке, отсутствии ответа, устаревшей дате, неверном update ID, отключённой авторизации, неуспешном API, повторе после таймаута и перезапуска.

Для живой приёмки **не удаляйте произвольные исторические сообщения**. Вручную отправьте тестовое сообщение от владельца, ответьте на него `/delete` и подтвердите исчезновение именно исходного сообщения. До этого шага статус — **local implementation + offline tested, not live verified**.
