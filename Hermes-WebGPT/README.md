# Hermes WebGPT Relay — исходники и проверка

Локальный провайдер для существующей связки Hermes → Web Companion → веб
ChatGPT. Публикуются код Relay и тесты; личные Telegram-токены, профили,
SQLite, браузерные настройки и конфиги расширения сюда не входят.

Изменения backend проверены и активированы на рабочем Windows-ПК 10.11.2026.
Это не утверждение о завершённой проверке каждой Telegram-команды или пяти
параллельных сессий. Архивы установщика от 4 ноября не пересобирались.

## Удаление сообщения Telegram по команде (11.11.2026)

Добавлена безопасная **owner-only** команда: ответьте **на своё** сообщение в Telegram текстом `/delete` или `Удали это сообщение`. Gateway проверяет реальный Telegram update, владельца, чат, топик, возраст сообщения (до 48 часов) и записывает intent до вызова API. Удаление чужих сообщений, сообщений без явного reply и неопределённых запросов запрещено. Таймаут не вызывает автоматического повтора.

Исходник: [`telegram_delete_control.py`](telegram_delete_control.py). Инструкция и ограничения: [Telegram owner delete](docs/TELEGRAM_OWNER_DELETE_RU.md). Изолированные тесты: [`test_telegram_delete_control.py`](patches/telegram-owner-delete/test_telegram_delete_control.py).

**Проверка:** локальный Windows Gateway SDK соответствует обработчику, 22/22 теста PASS без сети. **Статус активации:** локальные файлы обновлены, однако работающий Gateway должен быть перезапущен в контролируемом режиме. Реальное удаление в Telegram пока не подтверждено. Публичный `gateway_bootstrap.py` не содержит всех рабочих локальных overlay, поэтому **его нельзя вслепую заменять на действующем ПК**.

## Проверить код без аккаунтов и запросов модели

Python 3.10+, стандартная библиотека:

```powershell
py -3 -m unittest discover -s Hermes-WebGPT -p "test_*.py" -v
```

Эта команда запускает 81 опубликованный тест backend, совместимости Windows и диагностики с синтетическими
данными и локальным HTTP. Тесты RSS подменяют загрузку источников и не ходят
в интернет. Отдельно доступна [диагностика очереди](monitoring/queue_monitor.py).

В Windows-проекте также выполнены 69 существующих регрессий: итоговая
проверка новой сборки — 107/107 PASS. Проверены все 29 реально предложенных
Hermes схем инструментов; приватные исходные запросы тестов не опубликованы.

## Обновление 11.11.2026

Добавлены выбор установленного native agent-browser и существующего Edge на
Windows, read-only browser_preflight, сохранение публичных RSS-доказательств
между tool turns и расширенный монитор очереди. Инструкции для оператора,
отбор функций, 9 FR / 18 сценариев и границы проверки:
[SDD-дополнение](docs/RESPONSE_QUALITY_SDD_20261111.md).

Финальная проверка текущего Windows-проекта — 188/188 PASS без SKIP. В этом
репозитории опубликованы 81 root test и 38 monitor tests; ещё 69 прежних
регрессий выполнялись в существующем локальном проекте. На Linux одна проверка
изменения Windows resolver cache пропускается как неприменимая.

Монитор проверяется отдельно:

```sh
python -m unittest discover -s Hermes-WebGPT/monitoring -p 'test_*.py' -q
```

При установленном Hermes доступна диагностика без запуска браузера:

```sh
python Hermes-WebGPT/browser_preflight.py
```

Она различает наличие зависимостей и настоящую навигацию. Оператор может
добавить `--latency-target-seconds 120 --window-seconds 3600` к queue_monitor.
Его exit 1 означает обнаруженное внимание/историю, exit 2 — отсутствие данных.
Статус done и доля завершённых inference не доказывают Telegram delivery.

Проектный `gateway_bootstrap.py` используется существующим Gateway runner:
`from gateway_bootstrap import run; run()`. Конфигурация Telegram, источник
авторизации и настоящий профиль остаются в локальной установке. Публичный
[SOUL пример](config/SOUL.efficiency.example.md) не содержит пользовательских
данных. Новые CLI ещё не зарегистрированы как отдельные Hermes/MCP tools.

Реальная изолированная навигация Edge прошла на синтетической локальной
странице (open 1,62 с, get title 0,20 с, close 0,61 с). Полный новый Telegram
E2E и p50/p95 этой сборки пока не подтверждены. Каноническая запись нового SDD
ожидает штатного foreground owner approval точного плана.

## Что изменено

- Ошибка схемы аргументов становится типизированным отказом и терминальным
  состоянием запроса, не обрывом HTTP с зависанием Hermes.
- `multipleOf` проверяется без допуска, который раньше принимал числа рядом
  с разрешённым значением; некорректный делитель не обрушает обработчик.
- Ожидание ответа читает только state/reason; полный payload/result нужен
  один раз после завершения.
- Сжатие представления схем различает аннотации, имена параметров и буквальные
  значения. `title`/`description` как имена аргументов, enum/const/default,
  ссылки и неизвестные расширения сохраняются.
- Подготовка публичных RSS имеет общий бюджет ожидания 1,2 с, не более четырёх
  фоновых загрузок и обновляемый минутный cache key. Источники, превысившие
  бюджет, отмечаются как недоступные; их содержание не выдумывается.
- `/health.runtime_build` фиксируется при импорте процесса. Если файл позже
  заменён без перезапуска, запущенный процесс продолжает сообщать прежний SHA.

Сжатие пяти сохранённых запросов уменьшило представление для модели на
44,2–50,9% по символам. Это не измерение токенов или процента ускорения
полного Telegram-ответа. System/user-инструкции не обрезались этим изменением.

## Развёртывание и границы

Для новой изолированной установки Relay можно запустить:

```powershell
py -3 Hermes-WebGPT/relay.py --data C:\private\hermes-relay
```

Он создаёт собственную локальную авторизацию и слушает loopback. Не запускайте
второй экземпляр поверх действующего порта 18765. Запуск Relay сам по себе
не устанавливает Hermes Gateway, Telegram-бота или браузерное расширение.
Установка Web Companion выполняется штатным проверенным процессом проекта.

Для уже работающей установки обязательны SHA-сверка, резервная копия,
проверка принадлежности PID/порта и отсутствие активного задания перед
контролируемым перезапуском. Не переносите реальный auth/config в Git.
Не повторяйте неизвестный Send и не очищайте защитные записи очереди.

`web_manual_input` и ошибки DOM требуют проверки браузерного слоя. Работающий
HTTP endpoint не доказывает отправку в ChatGPT и доставку в Telegram.
Полная функциональная спецификация: [HERMES_FUNCTIONAL_SPEC_RU.md](../docs/HERMES_FUNCTIONAL_SPEC_RU.md).
