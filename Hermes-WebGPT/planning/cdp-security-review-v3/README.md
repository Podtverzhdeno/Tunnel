# Hermes CDP Security Patch v3 — staging-only

**Статус:** пакет протестирован в изолированном Linux-контейнере; **НЕ установлен на Windows-вариант Hermes** и **НЕ разрешает работу с настоящим ChatGPT Web**. Local Workspace при последней проверке возвращал `UNAVAILABLE / MCP SSE probe 429`.

## Назначение

Пакет защищает *тестовый* отдельный Playwright/CDP-обработчик от ошибочного подключения к рабочему Relay. Перед первым `/bridge/claim` обработчик требует challenge-response HMAC-SHA256 от специально подготовленного **временного** Relay, работающего на `127.0.0.1`.

Используются независимые одноразовые ключи: `HERMES_CDP_FIXTURE_PROOF_KEY` и `HERMES_CDP_FIXTURE_WORKER_KEY`. Проверка также полностью запрещает HTTP-редиректы и прокси. Она **не** даёт право входить в существующий пользовательский браузер, не подтверждает ответ ChatGPT и не заменяет настоящую авторизацию production.

## Что изменено в v3

В отличие от v2, установщик staging дополнительно защищён от управляемых частичных записей:

- Источники и добавляемые файлы проверяются по встроенным SHA-256. При несовпадении установка не начинается.
- Файлы предварительно записываются полностью и `fsync`-ятся. **Новые файлы и резервные копии** публикуются исключительно через атомарное создание hardlink без перезаписи чужих файлов. Если том не поддерживает hardlink, установщик отказывает, не переходя к небезопасной записи.
- Два существующих файла обновляются в порядке: сначала **тестовый запускатель**, затем **обработчик**, чтобы снизить вероятность частичной активации.
- Перед каждым изменением проверяется предыдущий SHA; после — новый. Одноразовый lock-файл снабжён случайным маркером, и установщик удаляет его только при сохранении владения.
- При обычных ошибках выполняется **условный откат**: возвращаются исключительно файлы, в которых по-прежнему находятся байты именно этого патча. Изменения другого процесса сохраняются и отдельно помечаются как конфликт для ручной проверки.
- Учитывается случай, когда системный вызов сообщил об ошибке **уже после** выполненной записи. Проверка реально установленного SHA позволяет корректно выполнить откат.
- Резервные копии исходников остаются для аудита даже после успешного автоматического отката.

Это **не полноценная атомарная транзакция**: аварийное отключение питания или `os._exit` в ходе установки может оставить частичную staging-версию и lock-файл. Не запускайте CDP-обработчик до повторной проверки и завершения всех тестов.

## Состав

- `fixture_relay_attestation.py` — HMAC-подтверждение временного Relay, без перенаправлений.
- `test_fixture_relay_attestation.py` — позитивные и негативные тесты протокола.
- `apply_guarded_patch.py` — `--plan` по умолчанию; `--apply` только для staging и только при совпадении SHA.
- `test_apply_guarded_patch.py` — исходные тесты проверки установки.
- `test_checked_rollback.py` — тесты частичной записи, состязательных изменений, блокировки и условного отката.
- `SECURITY_REVIEW.md` — границы доверия, ограничения, сценарии отказа.
- `UNIT_TEST_RESULTS.txt` — фактический лог проверки.
- `SHA256SUMS.txt` — SHA-256 содержимого архива (кроме самого manifest).

## Самостоятельная проверка пакета

В распакованной папке:

```powershell
py -3 -m unittest -v test_fixture_relay_attestation.py test_apply_guarded_patch.py test_checked_rollback.py
```

Проверка пакета на Linux: **37 тестов успешно, 0 ошибок, 0 пропусков**. Это не заменяет интеграционный Windows/Edge тест.

## Подготовка к staging-установке в Hermes (после восстановления доступа)

Держите распакованный пакет **вне** каталога `standalone-worker-v2`. Из PowerShell в корне `Hermes-WebGPT`:

```powershell
$target = (Resolve-Path '.\planning\cdp-live-preflight-20261111\standalone-worker-v2').Path
$patcher = 'ПУТЬ_К_ПАПКЕ_Hermes_CDP_fixture_security_patch_v3\apply_guarded_patch.py'
py -3 $patcher --target $target
```

Это read-only план. Для применимости требуется точное совпадение двух SHA-256 ранее проверенных исходников:

- `fixture_worker.py` — `33f0b16ffedac9d15e3d88963ace48ffcccdcd6325a39984932103ccb9125f79`.
- `test_worker_subprocess_e2e.py` — `c2f30b852597ce0693d5d54b51d69942af04d2319b8376a46cb75aaebf6a6bad`.

**При несовпадении SHA остановитесь:** новый исходник нужно проверить и перебазировать патч, а не отключать защиту. Убедитесь, что другой агент сейчас не пишет в staging. Только после проверки плана:

```powershell
py -3 $patcher --target $target --apply
```

## Не изменяется

Рабочий `relay.py`, Gateway, расширение Web Companion, Telegram, существующие браузерные профили, cookies, ключи и база текущих запросов. Пакет не публикуется в GitHub автоматически, не устанавливает сервис и не включает production-транспорт.

**Главные нерешённые условия:** отдельный защищённый профиль Edge с ручным входом; настоящее выполнение ChatGPT Web Send и подтверждение ответа для `request_id`; строгая связка Telegram Bot API final ACK; NTFS ACL и crash/power-loss durability; согласование с действующей очередью и noReplay-флажками.
