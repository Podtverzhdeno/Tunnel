# Требования: Hermes, Telegram и Web Companion

Статус: требования и критерии приёмки. Документ не утверждает, что все пункты
реализованы. Дорабатывается существующее решение, без замены проекта.

## Расширение: два основных раздела

- **Ручной ввод сессий:** до пяти разных сохранённых URL ChatGPT; подключение
  уже открытых вкладок и создание неактивных вкладок для остальных. Валидация
  URL, удаление дубликатов, отдельные статусы каждой сессии, общий полный пульт.
- **Автоматически:** создание выбранного числа сессий из разрешённого запуска,
  ввод общей задачи или отдельных ролей, проверка фактического подключения и
  первой отправки. Открытая вкладка сама по себе не означает запуск агента.
- Общие настройки: сообщение продолжения, максимальное число циклов или
  продолжение до остановки; Start/Pause/Resume/Stop для каждой сессии и всех.
- Следующий ход разрешён только после подтверждённого завершения ответа в том
  же диалоге. Продолжение в новом чате требует подтверждённой связи с исходным.
- Лимит ChatGPT, вход, ручной текст, явная остановка, неизвестный Send и ошибка
  привязки ставят соответствующую сессию на паузу с понятной причиной.
- Сбой одной сессии не должен дублировать отправку в остальных. После перезапуска
  расширение сверяет устойчивое состояние, принадлежность вкладок и активные
  задания. Оно не создаёт окна без пользовательского запуска.
- Видимая диагностика: последняя команда, время последнего подтверждённого
  события, версия активного worker, состояние очереди, причина паузы и
  конкретный следующий шаг. Нажатие «включить» обязано дать подтверждение или
  ошибку; молча менять лишь локальный флаг недостаточно.

## Hermes → веб ChatGPT → Telegram

- Используется локальный совместимый провайдер, отдельная привязка request ID,
  lease и собственной фоновой вкладки к каждому запросу. Одна исходная
  Telegram-команда может вызвать несколько последовательных запросов модели.
- Сериализация сообщений и предлагаемых Hermes-инструментов; строгий ответ
  JSON с совпадающим request ID. Только разрешённые имена инструментов и
  валидные аргументы. Инструменты исполняет Hermes, затем передаёт результаты
  следующему запросу модели. Чужой ответ или декоративный UI-текст не принимается.
- Итоговый ответ должен вернуться обычным ответом Hermes в исходный Telegram
  чат/тему, с учётом лимитов Telegram и без диагностической копии вместо результата.
- Явные Enable/Disable передачи, подтверждение фактического подключения,
  ограниченная очередь и понятный отказ при недоступности сервиса.
- Включение High для Hermes — проверяемое предпочтение, не бесконечный блокер
  передачи при неподтверждённом UI. Отдельные строгие режимы циклов сохраняют
  свою настройку. Выбранный режим и результат проверки видны пользователю.
- Входящий Telegram доступ ограничивается настроенными владельцами. Группа
  не расширяет allowlist автоматически. Privacy mode, упоминания, ответы,
  темы и права отправки проверяются отдельно. Home channel задаётся отдельно.
- Ограничение контекста и сжатие с сохранением tool-пар; переполнение ловится
  до зависания браузера. Требования Hermes к минимальному заявленному контексту
  проверяются при конфигурации. Никаких выдуманных результатов инструментов.
- Stop/Reset/отмена обрабатываются согласованно в Gateway и Relay. Неопределённая
  отправка сохраняется как неопределённая и не воспроизводится автоматически.

## Восстановление и резервный способ

Основной транспорт — существующее расширение. Резервное управление вебом
допустимо после проверки его готовности и принадлежности страницы. Оно не
должно перехватывать чужую вкладку, менять транспорт уже начатого запроса или
повторять потенциально совершённый Send. Абсолютный XPath из старого UI —
только диагностический ориентир; рабочая реализация проверяет актуальный
редактор, кнопку, состояние страницы и идентичность запроса.

До Send ограниченный повтор bootstrap разрешён только в том же документе с
проверкой уже работающего runner. После Send требуется наблюдение сохранённого
сообщения; потерянный ACK не является разрешением отправлять повторно.
Защитные записи перед освобождением слота сохраняются с запретом replay.

## Наблюдение, скорость и приёмка

Метаданные наблюдения, раздельные стадии, тесты и план ускорения описаны в
[HERMES_MONITORING_RU.md](HERMES_MONITORING_RU.md). Монитор обязан отличать
отсутствие доступа от здорового состояния, а новые сбои — от старой истории.
Секреты, реальные конфиги, SQLite, переписка и браузерные профили не публикуются.

Минимальная живая приёмка после восстановления доступа:

1. Новый Telegram текст проходит полный путь и возвращает ожидаемую уникальную
   метку без дублей; затем проходит запрос с одним разрешённым инструментом.
2. Ручной текст остаётся нетронутым; неизвестный Send не повторяется; ошибка
   JSON или чужой request ID не превращается в ответ пользователю.
3. Пять разных ручных URL и пять автоматически созданных сессий проверяются
   отдельными прогонами: старт, завершение, продолжение и остановка каждой.
4. Проверены пауза, лимит, потеря связи, перезапуск worker и изоляция сессий.
5. Для каждого прогона зафиксированы фазы, число отправок, исход и независимое
   подтверждение результата. Прохождение unit-тестов не заменяет этот прогон.

## Уточнение восстановления и бюджета backend, 10.11.2026

- Непустой редактор сам по себе не разрешает очистку. Замена допустима только
  для точного черновика собственного терминально заблокированного запроса
  до Send, с проверенными ID/lease/document/window, неактивной вкладкой и
  состоянием нового запроса claimed без серверного tab.
- До замены сохранить исходный черновик в локальном карантине, подтвердить
  запись чтением и сохранить noReplay старой попытки. Неизвестный текст,
  вмешательство пользователя и uncertain/done предыдущего запроса блокируют
  замену. Не передавать текст черновика в диагностические журналы.
- Потеря ACK intent допускает ограниченные read-only сверки его состояния
  перед первым click; повторный intent/Send не допускается. После async
  проверки или предупреждения повторно проверить точный редактор и текст.
- Ошибочные схемы инструментов должны давать явный терминальный отказ,
  а не незавершённый HTTP. Сжатие схем сохраняет имена параметров, enum,
  const/default, ссылки и смысл ограничений. Недопустимо заменять реальные
  tool-результаты синтетическим ответом.
- Подготовка RSS ограничена общим временем ожидания 1,2 с и четырьмя
  параллельными загрузками; истёкший бюджет обозначает недоступность источника.
  Кэш обновляется по времени. Снижение символов измерять отдельно от токенов
  и задержки полного Telegram-ответа.
- Сверять код запущенного Relay через runtime_build, зафиксированный при
  старте процесса. SHA файлов на диске и публикация extension revision
  не являются подтверждением загруженной версии.

Результат текущего цикла: 107 backend-проверок в Windows; 38 из них публикуются
в репозитории. Восстановление черновика — 25 новых + 36 существующих тестов и
три Native Edge MV3 сценария на подменённых страницах. Источники и установленная
копия расширения синхронизированы, публикация прошла штатную проверку.
**Новая живая Telegram-приёмка этой сборки пока не подтверждена.**
