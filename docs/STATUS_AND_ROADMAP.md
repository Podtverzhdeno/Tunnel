## Что осталось: приоритеты и критерии завершения

### P0 — Protected host / P085 (блокер Trusted)

**Нельзя полностью выполнить одной правкой Python в агентском репозитории.** Нужен отдельный доверенный Windows broker: независимые principals/SIDs, ACL на исполняемые файлы, Python, policy и journal, проверяемый выпуск разрешений и реальная двухсторонняя E2E-проверка. Только после установки владельцем на защищённом хосте можно подключить проверку к `trusted_host_attested()`.

**Готово, когда:** подлинные доверенные principal и policy подтверждены на уровне ОС; тесты deny/allow/forgery/restart отрицательные и положительные проходят; только после этого `effective_mode=trusted`. Не заменять проверку на `True`, JSON-флаг или собственный отчёт агента.

### P0 — Chain2 acceptance / разбор неопределённых ACTIVE

Необходимо сверить 9 `active` с фактическими веб-чатами/отчётами/ACK, завершить/отклонить непроверенные этапы; не повторять неизвестные отправки без владельческого подтверждения.

**Готово, когда:** `chain2_fully_accepted=true`, нет двусмысленных ACTIVE/ACK, у принятых этапов проверены реальные отчёты и допустимая цепочка ancestry. Пока Chain3 не может выпустить первого потомка.

### P1 — End-to-end on another Windows account

После `git clone` выполнить локальный тест `py -3 scripts\\verify-portable-install.py --test-powershell`, установить свой `tunnel-client`/custom MCP, подключить браузер и отправить **один** разрешённый тестовый prompt. Проверить `message_saved` и `REPORT_ACKED`, отсутствие повтора после рестарта.

**Готово, когда:** E2E пройден на независимом аккаунте с собственными ключами и `tunnel_id`; в README зафиксированы реальные версии и устранены блокирующие несовместимости.

### P1 — Непрерывный полезный цикл и наблюдаемость

Довести возобновляемые задания Developer → Reviewer → Developer до полезной работы; добавить отчётливые состояния `waiting/blocked/active/completed`, устойчивый журнал, лимиты повторов/частоты, операторский `Start/Stop`. Чистый локальный bridge и расписание **не** являются гарантией вечной генерации в браузере.

**Готово, когда:** тест ≥3 последовательных поколений с доказанными `report SHA`, owner-consented sandbox scope, recovery без дублирующей отправки, отказ при пустой/непринятой работе. Подписка и платформа всё равно ограничивают работу модели.

### P2 — Достоверная токенная телеметрия

Сейчас «326 500 токенов/мин» — только выбранный пользовательский **сценарный эквивалент** другого стенда, не фактический счётчик нашей фабрики.

**Готово, когда:** для API-агентов собираются реальные usage-поля (input, cached input, output, model, цена), для ChatGPT UI-сессий отдельные wall-clock/runtime и `usage_unknown`; источники не складываются повторно.

### P2 — Упрощение запуска/управления Windows

Добавить добровольный пользовательский launcher/supervisor для независимого старта MCP observer, bridge и tunnel-client, и диагностическую команду, показывающую, **что именно не готово**, без записи секретов в лог. Планировщик Windows Task Scheduler только по явному выбору владельца; не устанавливать системную службу молча.

**Готово, когда:** запуск, проверка доступности, завершение и повторный запуск проходят в чистой Windows VM без лишних процессов или повторной отправки веб-задач.

## Важные границы

- `observer` — ограниченный read-only HTTP MCP. Для выполнения Git, записи и команд в ChatGPT необходим доверенный механизм исполнения и соответствующие права, а не изменение одного флага.
- Локальный `observer-authorization-header` не является токеном OpenAI API и не удостоверяет владельца Windows. Его нельзя публиковать.
- Не считайте `message_saved`, `tab_closed`, количество тестов или созданных отчётов эквивалентом модельных токенов либо доказательством полезно завершённой задачи.
